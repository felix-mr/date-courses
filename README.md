# Date Courses

둘이 함께 관리하는 데이트 코스 기록.

## 구조

```text
courses/
  YYYY/
    YYYY-MM-DD-지역-짧은-이름/
      README.md
      course-options.html
templates/
  course-readme-template.md
```

## 기록 규칙

1. 새 코스마다 `courses/YYYY/YYYY-MM-DD-지역-짧은-이름/` 생성.
2. 계획 단계에는 `README.md`와 모바일용 공유 HTML을 추가.
3. 다녀온 뒤 같은 `README.md`의 후기만 업데이트하고 원래 계획은 보존.
4. 카테고리는 바다 / 맛집 / 드라이브 / 글램핑 / 1박 / 후보조사처럼 기록.
5. 음식점 메뉴·숙소·운영시간은 수정할 때 웹에서 다시 확인하고, 확인일과 출처를 남긴다. 당일 재고·영업은 확정으로 쓰지 않는다.
6. 새 기록을 추가하거나 기존 날짜를 수정하면 이 목록과 루트 `index.html`·`wishlist.html`·`history.html`와 목록 데이터 `assets/travel-records.js`도 함께 갱신한다. 기존 기록은 삭제하지 않는다.
7. 숙소·식당·관광지 등 장소에는 모바일에서 열 수 있는 네이버 지도 검색 링크를 붙인다. 검색 결과의 실제 장소는 확인한다.
8. 국내·해외 구분과 국가·지역을 기록한다. 홈에서는 지역 구분과 여행 테마를 함께 선택할 수 있다.
9. 날짜 미정인 미래 후보는 조사일을 폴더 날짜로 사용하고 README와 HTML에 여행 날짜가 미정임을 명시한다. 날짜가 확정되면 실제 여행일 폴더에 새 일정을 추가하고 후보 원본은 보존한다.
10. 비개발자가 읽는 공유 페이지는 일정과 장소 카드를 중심으로 구성한다. 지도 버튼은 문장 사이에 넣지 않고 카드 하단에 둔다. 같은 설명은 반복하지 않는다. 공통 확인 사항은 한 곳에, 출처는 접어둔 안내에 모은다.

## 공유

목적에 따라 세 페이지로 나눠 탐색합니다.

- `index.html` — 다가오는 여행. 실제 여행 날짜가 정해진 일정만 표시합니다.
- `wishlist.html` — 가보고 싶은 곳. 날짜 미정인 국내 17개·해외 1개 후보를 지역·테마로 고릅니다.
- `history.html` — 과거 내역. 다녀온 여행, 방문 확인 전인 지난 일정, 지난 후보 조사를 구분합니다.

현재 다가오는 여행 1개·날짜 미정 후보 18개·과거 내역 4개입니다. 대천 숙소 휴식·우유창고·해미읍성 방문은 사용자 확인으로 기록했습니다. 수원·동탄은 사용자 확인으로 방문 완료이며, 9월 29일·30일 후보 조사는 실제 방문 기록과 구분합니다. 조사일이 오래됐다는 이유로 미래 후보를 과거 여행으로 분류하지 않습니다. 실제 일정은 한국 시간 기준 종료일 다음 날부터 지난 일정으로 이동하며, 방문 완료는 사용자 확인 뒤 기록합니다. 구분과 종료일은 `assets/travel-records.js`에서 관리합니다. 기존 홈의 `#wishlist` 링크는 새 후보 페이지로 연결됩니다. 해외 후보는 사용자 요청 시 추가합니다.

공유 주소: https://felix-mr.github.io/date-courses/

홈과 최신 대천 일정, 미래 여행 후보는 `assets/site.css`를 공통으로 사용합니다. 기존 코스 폴더와 공유 주소는 보존합니다.

## 꾸미기

사용자가 제공한 꿈나라키티 테마의 연분홍·갈색 색감과 원본 키티 그림을 사용하고, 여행·구름 포즈의 생성 이미지를 함께 배치합니다. 장식은 반투명으로 표시하며 본문과 잠깐 겹쳐도 움직임이 끊기지 않도록 유지합니다. 버튼 클릭은 막지 않습니다. 떨어지는 키티는 첫 화면부터 2개가 보이며, 모바일 최대 3개·큰 화면 최대 5개로 제한합니다. 반투명으로 화면 가장자리에서 표시하며, 목록 페이지 상단에서 켜고 끌 수 있습니다. 상세 페이지에서는 머리글 바로 아래에 표시합니다. 기기의 움직임 줄이기 설정과 효과 끄기 선택을 따릅니다. 이미지 출처는 `assets/kitty/README.md`에 남깁니다.
